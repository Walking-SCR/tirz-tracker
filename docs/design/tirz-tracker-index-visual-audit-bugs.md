## 走查范围与证据

- 目标稿：`tirz-tracker-iphone17-promax-v4.png`（首页基准）与 V6 交互状态稿（来源选择、识别中、异常、给药设置、记录详情等弹层）。
- 实现：根目录 `index.html`，并核对 `public/index.html` 与 Worker 静态兜底页的同步约束。
- 证据：使用 Chrome 打开本地 `index.html` 完成真实页面截图，并打开“记录今日体重”来源选择弹层；同时结合代码尺寸、层级和组件结构逐项核对。
- 限制：当前环境没有 iPhone 17 Pro Max 真机或浏览器设备模拟，截图包含桌面浏览器外壳；安全区与真实状态栏以 CSS 静态检查和 iOS PWA 规范复核。

## 问题清单

| 编号 | 优先级 | 模块 | 现象与设计差异 | 根因 | 验收标准 |
|---|---|---|---|---|---|
| UI-001 | P1 | 顶部 Hero | 实现使用 sticky 玻璃顶栏、底部边框和较小的图标/标题；设计稿是无卡片感的 Hero 区，标题、同步状态和日期层级明显更大。 | `appHeader` 复用了通用 `glass-surface`，字号为 `text-sm/text-[11px]`，图标仅 32px。 | 首屏顶部无横向玻璃条；图标约 44px，标题约 24px，副标题/同步日期约 14px，并保留 safe-area 顶部空间。 |
| UI-002 | P1 | 指标卡 | 目标体重、当前体重、累计净减的数字在实现中偏小，首屏视觉重点不足。 | 指标值使用 `text-xl`、标签使用 `text-[11px]`。 | 三列仍保持一行；标签约 14px、数值约 30px，单位弱化但不挤压数值。 |
| UI-003 | P1 | 趋势区 | 实现把趋势区做成完整玻璃卡片，和设计稿的开放式图表区不一致；标题、切换器、图表整体偏小。 | `trendSection` 使用 `glass-surface rounded-2xl p-4`，图表固定 `h-52`。 | 趋势区无外层圆角卡片；标题约 20–24px；图表高度约 240–288px，切换器保持右对齐。 |
| UI-004 | P1 | 趋势图 | 当同一天有多条记录时，x 轴日期和数值标签密集重叠，截图中出现连续重复的日期/数字。 | 图表直接使用原始记录，没有按日期聚合；x 轴允许自动旋转，数据标签逐点绘制。 | 同一天只显示当天最后一条记录；x 轴标签水平、最多 11 个刻度，数字标签可读且不互相覆盖。 |
| UI-005 | P1 | 主操作区 | “记录今日体重”与“手动补录”层级比设计稿弱，按钮高度和图标偏小。 | 主按钮为 `h-14/text-base/text-xl icon`，次入口为 `text-xs`。 | 主按钮高度约 64px、图标约 24px；手动补录约 14px，仍保持唯一高强调 CTA。 |
| UI-006 | P1 | 疗程时间轴 | 实现使用玻璃卡片包裹时间轴；设计稿使用上下分隔线、节点更大、日期/周几更清楚。 | `treatmentTimeline` 复用 `glass-surface`；节点 28–32px，文字 9–10px；连接线仍按 22px 定位。 | 时间轴使用上下分隔线而非外层卡片；节点约 36–40px，连接线穿过节点中心，文字至少 11–12px。 |
| UI-007 | P1 | 记录明细 | 记录卡的图片和体重主数值偏小，首屏中记录信息的视觉权重低于设计稿。 | 图片 64px、体重 `text-2xl`，卡片高度约 92–108px。 | 图片约 80px、体重约 30px；仍按“图片 + 文本/数据/操作按钮两行”展示，备注单行截断。 |
| UI-008 | P2 | 动态数据 | 本地运行截图显示 168.3 斤、-6.4 斤、13 条等运行时数据，与设计稿的 169.5 斤、-5.2 斤、8 条不一致。 | 页面使用 localStorage/云端真实数据，设计稿使用固定示例数据。 | 不强行写死业务数据；视觉验收使用 fixture/空数据快照，真实运行继续显示用户数据。 |
| UI-009 | P2 | 弹层一致性 | 来源选择弹层功能齐全，但桌面截图中尺寸按桌面居中，无法直接证明 iPhone 底部 sheet 的 safe-area 和触控尺寸。 | `@media (min-width:640px)` 会切换到居中 dialog 形态；当前无设备模拟。 | iPhone 宽度下保持底部 sheet、底部安全区和最小 44px 触控目标；桌面形态仅作为辅助预览。 |
| UI-010 | P2 | 可访问性 | 图标按钮和图片操作主要依赖 title/视觉图标，部分控件缺少统一 aria-label。 | V6 先保证交互 ID 和视觉实现，未统一无障碍属性。 | 关闭、同步、换图、删除、查看图片等图标按钮均具备可读 aria-label，不改变视觉稿。 |

## 已确认的结构完整性

- 首页顺序已符合需求：指标卡 → 趋势 → 记录今日体重 → 疗程时间轴 → 记录明细。
- 近 7 天、近 1 个月和累计切换入口存在。
- 来源选择、确认称重、更换图片、20 秒识别中、超时/格式异常/上传失败状态、给药配置、删除确认、会话与同步弹层均存在对应 DOM ID。
- 记录明细已经采用“图片 + 两行文本/数据 + 操作按钮”的布局基线，本轮只调整尺寸和层级。
